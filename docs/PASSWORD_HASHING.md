## What is /dev/urandom bytes?

`/dev/urandom` is a special device in Unix/Linux that generates random bytes. These bytes have high entropy, 
meaning they are unpredictable and suitable for cryptographic use, like creating salts.


The columns mean:

- First column (`00000000`, `00000010`, …) → the offset in bytes from the start of the file.
- Middle columns (`19 66 94 07 ...`) → the hexadecimal representation of the raw bytes.
- Right column (`|.f........gY.YU.|`) → the ASCII interpretation of those bytes (non-printable bytes are shown as .).

## What are salts?

A salt is a short sequence of random bytes used when hashing passwords. Its purpose:

- Uniqueness – prevents attackers from using precomputed hash tables (rainbow tables).
- High entropy – makes each password hash unique, even if two users have the same password.

So yes: `salts` are randomly generated bytes that make password hashing more secure.

### the problem...

```shell
$ echo -n "password" | sha256sum
5e884898da28047151d0e56f8dc6292773603d0d6aabbdd62a11ef721d1542d8  -
```

This always generates the same hash for the same password.
An attacker can use Rainbow Tables to crack it.

#### The solution: use a salt

If you combine your password with a salt (a random sequence of bytes), each hash becomes unique.
Even if two users have the same password, the hashes will differ, making precomputed attacks impossible.

```shell
$ SALT=$(head -c 8 /dev/urandom | base64)
$ echo -n "${SALT}password" | sha256sum                                                                                                         ✹
812a9c1796c740165a306c0cbae3048a7058ac0f5b9d57d12fd76b8abe628ca6  -
```
